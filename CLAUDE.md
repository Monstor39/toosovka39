Проект и общение с пользователем — на русском.

## Что это

Одностраничный сайт вечеринки DUBAI PARTY + Telegram-бот охраны, который проверяет и гасит коды на входе. **Вход бесплатный для всех**: гость заполняет короткую анкету (телеграм или телефон) и сразу получает код — это же и запись в базу гостей. Платный вариант один — стол с депозитом (боевая оплата ЮKassa). Node.js + Express, ES-модули (`"type": "module"`), без фронтенд-фреймворка (ванильный JS в `public/`).

## Команды

```bash
npm install        # зависимости (только express + dotenv)
npm start          # прод-запуск: node server.js  → http://localhost:3000
npm run dev        # разработка с авто-перезапуском: node --watch server.js
```

- Тестов, линтера и сборки в проекте **нет**. Быстрая проверка синтаксиса: `node --check server.js`.
- На Windows пользователь запускает двойным кликом `Запустить сайт.bat` (ставит зависимости при первом запуске и открывает браузер).

## Архитектура

`server.js` — единственная точка входа. **Первой строкой грузит `dotenv/config` до всех импортов** — иначе бот не увидит токен. Поднимает Express (API + отдача `public/`) и в конце вызывает `startBot()`.

**Единый источник правды — `config.js`.** Здесь мероприятие, варианты входа, цены, лимиты, форматы кодов и `manualTicket` (коды, которые владелец выдаёт из бота вручную). Цены и лимиты живут только на сервере и не принимаются из браузера. `TEST_MODE` вычисляется автоматически: пусто в `YOOKASSA_*` → тест-режим (оплата стола имитируется, код выдаётся сразу в ответе `/api/checkout`).

**Два варианта: `free` и `vip`.** У `free` цена `0` и `deposit: false` — оплаты нет вообще (ЮKassa не примет платёж на 0 ₽), код выдаётся прямо в ответе `/api/checkout`, депозита на баре нет. У `vip` (стол, 10 000 ₽, `limit: 4`) цена = депозит на баре. `maxQty` ограничивает, сколько кодов можно взять за раз (6 и 2). Охрана видит разницу и в боте, и на `/admin.html`: «депозит 10 000 ₽» либо «без депозита».

**Промокодов и колеса CRAZY DUBAI больше нет** (убраны 1 августа 2026 вместе с розыгрышем iPhone, когда вход сделали бесплатным). Удалены `lib/promo.js`, `lib/wheel.js`, эндпоинты `/api/promo` и `/api/wheel/spin`, поля `promo`/`wheel` у новых записей и `db.spins`. В старых записях `data/db.json` эти поля могут остаться — они просто не читаются.

**Бесплатный вход (основной путь).** `POST /api/checkout` с `ticketId: "free"`: сервер проверяет контакт (телефон или `@nickname`), выдаёт коды сразу, пишет заказ через `addOrder` и шлёт владельцу уведомление «🆕 Новая анкета». Никакой ЮKassa — ветка `TEST_MODE || total === 0`.

**Боевой путь оплаты стола (ЮKassa, `lib/yookassa.js` + `server.js`):**
1. `/api/checkout` **синхронно** резервирует стол pending-заказом на 20 минут (`addPendingOrder` до первого `await` — защита от гонки; свободный остаток = `limit − soldCount − pendingQty`), затем `createPayment` (redirect-flow, `capture: true`, `metadata.orderId`) и отдаёт `paymentUrl`. При ошибке создания платежа — `markOrderCanceled` (снятие резерва).
2. Коды выдаются **только после подтверждения оплаты** — двумя путями:
   - вебхук `POST /api/yookassa/webhook` (настроен в кабинете ЮKassa на `https://toosovka39.ru/api/yookassa/webhook`, события `payment.succeeded`/`payment.canceled`);
   - страховка: фоновый опрос каждые 30 сек всех pending-заказов с `paymentId` (на случай недоставленного вебхука).
   Оба пути идут через общий `processPayment()`: уведомлению **не доверяем**, статус перепроверяется прямым `getPayment(id)`; не-платёжные события (`refund.*`) вебхук подтверждает 200 и игнорирует.
3. ЮKassa возвращает покупателя на `public/success.html?order=<id>` — страница опрашивает `/api/order-status` каждые 3 сек (до 2 минут) и показывает коды.

**Данные — JSON-файл `data/db.json`** через `lib/db.js` (своя мини-БД, без внешних зависимостей). Ключевые моменты:
- Все записи (`addOrder`, `addPendingOrder`, `markOrderPaid`…) **синхронные, без `await`** — проверку остатка и сохранение в `server.js` нельзя разрывать через `await`.
- Статусы заказа: `pending` → `paid` | `canceled`. Жизненный цикл кода: создан → `used` (проход на входе) → `left` (ушёл). `counts()` даёт `inside = entered − left`.
- `load()` умеет мигрировать старые записи (добавляет `left`/`leftAt`, `deposit`/`paidRub`/`noDeposit` кодам, `status`/`codes` заказам).
- В базе живут коды прошлых вечеринок с `ticket: "entry"`/`"standard"` — таких билетов в конфиге уже нет, поэтому везде обращение через `ticketById[...]?.`; на входе и на баре они продолжают работать по данным самой записи.
- У кода есть `spent` и `spends[]` — сколько бармены списали с депозита и каждое списание отдельно (для отмены ошибочного).
- Флаг кода `manual: true` — выдан вручную из бота (`issueCode`), а не куплен на сайте. Флаг `test: true` (`setTest`) — код остаётся рабочим на входе и на баре, но **исключается из всей статистики**: `soldCount`, `soldSum`, `counts`, `history`, `insideList`, `barList`, `spendHistory` и таблица в `/admin.html` его не видят. `codeExists`/`getCode` тестовые коды по-прежнему находят (иначе можно выдать дубль кода).
- Деньги считает `counts()`: `revenue` — выручка сайта (сумма `paidRub` кодов с сайта; бесплатные анкеты дают 0), `cash` — наличные за выданные вручную, `total` — вместе, `depositTotal` — сколько депозитов выдано всего, `manualDeposit` — из них по ручным кодам. `soldSum(ticketId)` — сумма по конкретному варианту.

**`lib/codes.js`** — генерация уникальных кодов по формату `{ letters, digits }` из `config.js`. Буквы `I` и `O` исключены (похожи на цифры).

**Telegram-бот охраны и бара — `lib/bot.js`.** Работает через **long-polling (`getUpdates`), НЕ webhook** — поэтому боту не нужны публичный домен, HTTPS или открытые порты. Авторизация — по кодовому слову `SECURITY_PASSWORD`, **одно на всех** (охрана, бармены, владелец); забывшим бот показывает подсказку `SECURITY_HINT` (само слово не пишет). Список авторизованных хранится в памяти и сбрасывается при перезапуске. UI — reply-клавиатура (Статистика / История проходов / Остатки на баре / Списания / Отметить уход / [Выдать код — только владельцу] / Выйти). «Статистика» показывает не только количество, но и деньги: сколько по каждому билету, выручка сайта, наличные, выданные депозиты и сколько на баре уже проели.

**Владелец в боте — по `TELEGRAM_ADMIN_CHAT_ID`, а не по паролю** (кодовое слово одно на всех, поэтому право выдавать деньги нельзя вешать на него). Только владельцу видна кнопка «🎁 Выдать код» и кнопка «🧪 Не считать (тест)» на карточке кода; охрана и бармены их не видят и получают «Это может только владелец», если callback придёт от них. Выдача: панель с быстрыми суммами депозита (`manualTicket.deposits`) → `db.issueCode()` пишет и код, и заказ (`ticket: "manual"`, формат кода 2 буквы + 3 цифры). Одной строкой: `выдать 1200 Ваня` (подарок) или `выдать нал 1200 Ваня` (гость заплатил наличными → сумма идёт в `paidRub` и в строку «наличными»); подарок можно потом перевести в наличные кнопкой (`setCashPaid`). Разбор `выдать …` стоит **до** регулярки «КОД СУММА», иначе бот примет «выдать 1500» за списание с кода.

Роль определяется не паролем, а состоянием кода: прислал код — **не заходил** → кнопки «Подтвердить проход» (охрана); **уже внутри** → карточка бара с остатком депозита и кнопками списания (бармен). Бар живёт в `db.spend` / `db.undoLastSpend` / `db.balanceOf`: списывать можно **только после прохода** (`not_entered`) и только в пределах депозита; каждое списание пишется в `code.spends`, последнее отменяется кнопкой. У билетов с `deposit: false` списывать нечего (`no_deposit`). Бармену быстрее всего слать `КОД СУММА` одним сообщением (`A42 350`); коды понимаются и в русской раскладке (`Ф42` → `A42`).

**`lib/telegram.js`** — `notifyAdmin()`: уведомление владельцу в ЛС о каждой анкете и брони (`TELEGRAM_ADMIN_CHAT_ID`), включая коды и остаток свободных мест.

**Фронтенд `public/`:**
- `index.html` → `app.js` — витрина (две карточки), FAQ, липкая кнопка и окно анкеты (`/api/status`, `/api/checkout`). Бесплатный вход показывает код прямо в окне; стол в боевом режиме уводит на `paymentUrl` ЮKassa.
- `menu.html` — **карта бара картинкой** (в интерфейсе везде «Карта бара», файлы остались `menu.*`), отдельная лёгкая страница (стили и скрипт внутри неё, шрифты не грузятся). Открывается и по короткой ссылке `/menu` — её отдаёт `server.js` через `sendFile`, без редиректа, потому что на эту ссылку ведёт QR-код со столов (`qr/menu-qr*.png|svg`, сгенерированы на `https://toosovka39.ru/menu`). Картинка лежит в двух видах: `menu.webp` (~370 КБ, основной) и `menu.jpg` (фолбэк в `<picture>`); исходный PNG на 2,3 МБ в репозиторий не кладём. Пока картинка летит по сети, на её месте стоит размытая мини-копия, вшитая в CSS строкой base64. Тап по меню приближает картинку к месту нажатия (класс `viewer--zoom`), пинч-зум разрешён специально — `maximum-scale=6` в мета-теге viewport.
- `success.html` — результат оплаты, скрипт встроен в страницу.
- `admin.html` — веб-страница охраны/базы заказов, скрипт **встроен в саму страницу** (не отдельный файл). Защищена паролем `ADMIN_PASSWORD`, который передаётся в API через заголовок `x-admin-password`.
- `public/script.js` — **не подключён ни к одной странице** (устаревший файл), не трогай его при правках витрины — правь `app.js`.
- **Яндекс.Метрика** (счётчик `110941103`) вставлена в `index.html` и `success.html`; цели: `checkout` (отправил анкету / пошёл платить за стол, в `app.js`) и `purchase` (увидел код — в `app.js` для бесплатного входа и в `success.html` после оплаты).

**Две разные авторизации, не путать:** бот охраны в Telegram — по `SECURITY_PASSWORD`; веб-страница `/admin.html` и её API-эндпоинты (`/api/verify`, `/api/checkin`, `/api/orders`) — по `ADMIN_PASSWORD`.

## Переменные окружения

`.env` **в `.gitignore`** (как и `data/`) — при деплое через git на сервер не попадает, переносить руками. Значения см. в `.env.example`. Для бота обязательны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `SECURITY_PASSWORD` (+ необязательная `SECURITY_HINT` — подсказка забывшим слово); для веб-админки — `ADMIN_PASSWORD`. `YOOKASSA_SHOP_ID` + `YOOKASSA_SECRET_KEY` включают боевую оплату (пустые = тест-режим); `RETURN_URL` на бою — `https://toosovka39.ru/success.html`.
